# Форма регистрации — учебный проект для семинара

Рабочая форма регистрации (телефон + пароль + подтверждение пароля) без сборки, чистый HTML/CSS/JS. Открывается прямо в браузере файлом `index.html`, никакой установки не требуется.

## Как использовать на занятии

1. Залейте этот проект в `main` — это ЭТАЛОННАЯ рабочая версия без багов.
2. Создайте 4 ветки от `main`, в каждой внесите один точечный баг (см. ниже) — это будут стартовые ветки для команд.
3. На занятии каждая команда получает свою ветку, копию репозитория (fork) или доступ на редактирование, и работает с ИИ, чтобы найти и исправить баг.
4. Каждая команда открывает Pull Request в `main`.
5. Вы по очереди мёржите PR, обновляете открытый `index.html` (или деплой) и показываете исправление на экране.


## Исправления в тестовой ветке `Test-gr2`

### Баг №1 — посторонние символы в номере телефона

**До исправления:** проверка удаляла все нецифровые символы и проверяла только количество цифр и начало номера. Поэтому номер `7a9991234567` проходил регистрацию, хотя содержал букву.

**После исправления:** проверяется вся введённая строка. Допускаются `+7` и следующие 10 цифр либо 11 цифр с начальной `7` или `8`. Буквы, пробелы, скобки, дефисы, точки и переводы строки отклоняются. Поддержка номера с начальной `8` сохранена.

**Commit:** [`aaed106`](https://github.com/yardoss/registration-form/commit/aaed106a4a6816dbfd5d1a492b3d1c405c01b3fc) — `Fix bug 1: validate complete phone input`.

**Проверка:** выполнено 17 локальных проверок формата номера: допустимые варианты, неверная длина и начало, буквы, знаки, пробелы и переводы строки.

### Баг №11 — неактивная кнопка без объяснения

**До исправления:** кнопка «Зарегистрироваться» была заблокирована, пока форма невалидна, но не объясняла, какие поля нужно исправить. При пустой форме сообщения об ошибках также отсутствовали.

**После исправления:** под кнопкой отображается сводная подсказка с требованиями к телефону, паролю и его подтверждению. Она появляется при открытии формы, обновляется при вводе и исчезает, когда все поля валидны. Подсказка использует существующие проверки формы; элемент создаётся автоматически, если его нет в HTML. Для доступности добавлены `role="status"` и связь с кнопкой через `aria-describedby`.

**Commit:** [`6fb2c74`](https://github.com/yardoss/registration-form/commit/6fb2c74f845a4da6c1dc8e383a779649f4f65bcc) — `Fix #11: explain disabled registration button`.

**Проверка:** локально проверены начальное состояние, обновление подсказки при вводе, требования к паролю, совпадение паролей, успешная отправка и повторная блокировка после изменения данных. Проверена работа с готовым элементом подсказки и без него, а также отображение в Chrome.

### Commit davabbb — исправление валидации пароля

**Автор в истории Git:** David Beylin (davabbb).

**Commit:** [`da64311`](https://github.com/ZValeriy/registration-form/commit/da643118740621ae221f093a5670a00c163e2bb8) — «я пофиксил валидацию пароля».

**До исправления:** проверялась только минимальная длина 8 символов. Проходили пароли из одних букв или пробелов; верхней границы длины не было.

**Изменения:**

- Пароль должен содержать от 8 до 30 символов.
- Пробельные символы запрещены.
- Обязательны хотя бы одна латинская буква, одна цифра и один спецсимвол.
- Добавлена функция `getPasswordErrorMessage`, которая объясняет конкретную причину ошибки: пробелы, длину или отсутствие нужного типа символов.
- Обработчик ввода пароля использует новую функцию сообщений. Индикатор силы пароля сохранён.

Подсказка из исправления №11 учитывает эти требования. Например, `abcdefgh` отклоняется, а `Abcdef1!` проходит проверку пароля; для регистрации также нужны корректный телефон и совпадающее подтверждение.
